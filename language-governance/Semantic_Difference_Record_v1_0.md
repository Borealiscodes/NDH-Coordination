### ⭐ 2 — GQL semantics (runtime language)

```
Language: GQL
Type: Operational Runtime Language

Semantics:
    - Executes queries and programs.
    - Has bytecode, runtime behavior, and evaluation rules.
    - Interacts with systems, data, and engines.
    - May activate geometry, rendering, or platform behavior.

Role:
    GQL is a defined runtime language. Its semantics are operational and
    execution-oriented, governed by its bytecode and runtime specification.
```

### ⭐ 3 — NDH Structural DSL semantics (meta‑language)

```
Language: NDH Structural DSL
Type: Constitutional Meta-Language

Semantics:
    - Defines structural and temporal behavior without executing it.
    - Has non-activating, declarative semantics.
    - Governs protocols, ledgers, membranes, and altitude constraints.
    - Must not activate geometry, routing, or sealed-layer logic.

Role:
    The NDH Structural DSL is a meta-language used to express NDH governance,
    structural rules, and temporal protocols. Its semantics are constitutional,
    not operational.
```

### ⭐ 4 — Semantic membrane clause

```
Membrane:
    A semantic boundary separates GQL and the NDH Structural DSL.

Boundary Rules:
    - Runtime semantics (GQL) must not be used to define structural protocols.
    - Structural semantics (NDH DSL) must not be used to execute runtime logic.
    - No artifact may simultaneously claim GQL and NDH DSL semantics.
    - NDH DSL artifacts may reference GQL behavior but may not invoke it.
    - GQL artifacts may consume NDH-defined structures but may not redefine
      NDH structural semantics.

Effect:
    This membrane prevents runtime activation from entering structural
    governance and preserves drift-neutral altitude behavior.
```
