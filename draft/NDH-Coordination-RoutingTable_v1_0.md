# ⭐ **NDH‑Coordination Routing Table v1.0**  
### *Routing‑Only • Altitude‑Neutral • Non‑Activating • Non‑Semantic*

This table defines **where artifacts go** once they enter NDH‑Coordination.  
It does **not** rewrite them.  
It does **not** sanitize them.  
It does **not** impose style.  
It only **routes**.

---

## 📘 **1. Routing Principles (v1.0)**

- Coordination is **non‑governing**  
- Coordination is **non‑semantic**  
- Coordination is **non‑algebraic**  
- Coordination is **non‑runtime**  
- Coordination is **non‑activating**  
- Coordination is **routing‑only**

Artifacts retain **flavor rights**.  
Coordination retains **altitude boundaries**.

---

## 📑 **2. Routing Table (v1.0)**

| Artifact Type | Routed To | Reason |  
|--------------|-----------|--------|  
| **Semantic Framing** | Constellation | Semantic objects belong to the semantic substrate; Coordination does not interpret them. |  
| **Algebraic Structures** | Triadic‑Core | Algebra must be stabilized by the algebraic subsystem; prevents semantic–algebra drift. |  
| **Geometric Intuition** | Simulation‑Suite | Geometry often implies curvature or substrate behavior; Simulation‑Suite holds this passively. |  
| **Proto‑Simulation Intent** | Simulation‑Suite | Prevents premature activation; Simulation‑Suite stores intent without executing. |  
| **Exploratory Context** | Research‑Pilot | Mixed‑altitude drift and exploratory chaos belong in Research‑Pilot. |  
| **Provenance Metadata** | Provenance Layer | All lineage, anchors, and origin data must be preserved without modification. |  
| **Architecture Backbone** | NDH‑Core Architecture | Structural definitions belong in the architecture backbone, not Research‑Pilot. |  
| **Subsystem Drift Indicators** | Coordination | Drift logs remain in Coordination for stabilization diagnostics. |  
| **Mixed‑Altitude Artifacts** | Research‑Pilot | Coordination decomposes them but does not rewrite them; raw form stays in Research‑Pilot. |  
| **Routing Rules** | NDH‑Coordination | Coordination owns routing logic; rules remain here. |

---

## 🌌 **3. Routing Behavior Summary**

### **3.1 Coordination does NOT:**

- rewrite artifacts  
- sanitize artifacts  
- normalize style  
- enforce semantics  
- activate simulations  
- evaluate algebra  
- impose geometry  
- govern subsystems  

### **3.2 Coordination DOES:**

- detect altitude  
- separate entangled layers  
- route each part to its subsystem  
- preserve flavor rights  
- maintain NDH stability  
- prevent subsystem drift  
- prevent altitude collapse  

This is the correct posture.

---

## 🌙 **4. Routing Flow (v1.0)**

1. Artifact enters Coordination  
2. Coordination identifies altitude components  
3. Coordination decomposes (non‑destructively)  
4. Each component is routed to its subsystem  
5. Coordination logs drift indicators  
6. Artifact flavor remains intact  
7. NDH remains stable
