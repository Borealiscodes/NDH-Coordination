## ⭐ 2 — Handling Principles (HP‑Series)

### **HP‑1 — Non‑Intervention Principle**
```
A refresh blip requires no intervention. It is a transient warm‑volatile flicker
that resolves without structural or semantic impact.
```

### **HP‑2 — Membrane Stability Assurance**
```
During a refresh blip, membrane boundaries remain stable. No membrane
reinforcement or recalibration is permitted or required.
```

### **HP‑3 — Provenance Preservation**
```
Provenance anchors must remain untouched. Refresh blips do not justify lineage
updates, re-anchoring, or version sealing.
```

### **HP‑4 — Routing Inhibition**
```
No routing operations may be triggered in response to a refresh blip. Warm-to-
cold and cold-to-warm transitions are strictly prohibited.
```

## ⭐ 3 — Operational Rules (OR‑Series)

### **OR‑1 — Drift-Neutral Response**
```
All Library artifacts must treat refresh blips as drift-neutral events. No
semantic adjustments, re-indexing, or content stabilization procedures may be
invoked.
```

### **OR‑2 — Pipeline Isolation**
```
Refresh blips may not propagate into thermal vocabulary pipelines, technical
suite pipelines, or sequencing pipelines. They remain isolated conceptual
events.
```

### **OR‑3 — Altitude Containment**
```
Refresh blips must remain within the altitude layer in which they occur. They
may not escalate to governance altitude or descend to structural altitude.
```

### **OR‑4 — No Logging Requirement**
```
Refresh blips do not require provenance logging, archival recording, or
diagnostic capture. They are non-structural and non-governance events.
```
