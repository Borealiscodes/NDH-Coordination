# ⭐ **NDH‑Coordination Simulation‑Suite Passive Interface v1.0**  
### *Passive Boundary • Geometry + Simulation Intent Routing • Altitude‑Neutral Interface*

## **1. Purpose**

This passive interface defines **how NDH‑Coordination interacts with NDH‑Simulation‑Suite**, the subsystem responsible for:

- geometric intuition  
- spatial reasoning  
- proto‑runtime behavior  
- simulation intent  
- dynamic structure (non‑activated)  

Coordination does **not**:

- run simulations  
- activate runtime behavior  
- evaluate geometry  
- compute dynamics  
- govern simulation logic  

It only **routes geometry and simulation intent** upward.

---

## ⭐ **2. Interface Role**

Simulation‑Suite is the **geometry + proto‑runtime altitude** of NDH.

Coordination’s role is to:

- detect geometric intuition  
- detect simulation intent  
- isolate spatial/dynamic components  
- preserve geometric flavor  
- prevent geometry → runtime activation  
- prevent geometry → algebra drift  
- prevent simulation → substrate drift  

This interface defines that boundary.

---

## ⭐ **3. Geometry + Simulation Indicators (Passive)**

Coordination identifies geometry and simulation intent using **passive indicators**, not evaluation:

- curvature  
- shape  
- spatial intuition  
- manifold behavior  
- dynamic phrasing (“move,” “flow,” “run,” “execute”)  
- proto‑runtime structures  
- simulation adjacency  

These indicators trigger routing to Simulation‑Suite.

---

## ⭐ **4. Passive Interface Table (v1.0)**

| Component Type | Indicator | Routing Behavior | Notes |
|----------------|-----------|------------------|-------|
| **Geometric Intuition** | curvature, shape, spatial form | Route to **Simulation‑Suite** | No geometric evaluation |
| **Manifold Behavior** | “fold,” “curve,” “expand” | Route to Simulation‑Suite | Preserve flavor |
| **Dynamic Phrasing** | “run,” “flow,” “move,” “execute” | Route simulation intent upward | Prevent activation |
| **Proto‑Runtime Structures** | loops, cycles, state changes | Route to Simulation‑Suite | Non‑activating |
| **Geometry Drift** | spatial intuition inside algebra | Isolate geometry; route upward | Decompose only |

This table defines the **geometry + simulation boundary**.

---

## ⭐ **5. Interface Rules**

### **Rule 1 — Passive Only**  
Coordination does not evaluate geometry or runtime behavior.

### **Rule 2 — Non‑Destructive**  
Geometric and dynamic components are preserved exactly as written.

### **Rule 3 — No Simulation Activation**  
Coordination does not trigger execution or runtime.

### **Rule 4 — No Geometric Normalization**  
Coordination does not simplify or restructure geometric intuition.

### **Rule 5 — Decompose Mixed Artifacts**  
Geometry and simulation intent are isolated from semantic or algebraic drift.

---

## ⭐ **6. Routing Flow**

```
Artifact enters Coordination
   ↓ detect geometric or dynamic indicators
Isolate geometry + simulation intent
   ↓ route to Simulation-Suite
Preserve geometric flavor
   ↓ prevent geometry → runtime activation
Coordination remains altitude-neutral
```

This is the correct geometry + simulation routing posture.
