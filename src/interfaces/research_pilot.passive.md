# ⭐ **NDH‑Coordination Research‑Pilot Passive Interface v1.0**  
### *Passive Boundary • Mixed‑Altitude Decomposition • Routing‑Only Interface*

## **1. Purpose**

This passive interface defines **how NDH‑Coordination interacts with NDH‑Research‑Pilot**, the subsystem responsible for:

- exploratory artifacts  
- expressive drift  
- mixed‑altitude content  
- early prototypes  
- chaotic or emergent structures  
- pre‑formalized ideas  

Coordination does **not**:

- interpret Research‑Pilot content  
- rewrite exploratory artifacts  
- normalize expressive drift  
- govern Research‑Pilot behavior  
- activate any subsystem logic  

It only **decomposes mixed‑altitude artifacts** and routes their components upward.

---

## ⭐ **2. Interface Role**

Research‑Pilot is the **mixed‑altitude exploratory layer** of NDH.

Coordination’s role is to:

- detect mixed‑altitude content  
- isolate semantic, algebraic, geometric, simulation, and provenance components  
- preserve exploratory flavor  
- prevent altitude collapse  
- prevent subsystem contamination  
- route components upward cleanly  

This interface defines that boundary.

---

## ⭐ **3. Mixed‑Altitude Indicators (Passive)**

Coordination identifies Research‑Pilot content using **passive indicators**, not interpretation:

- expressive drift  
- mixed semantic + algebraic phrasing  
- geometry inside narrative  
- simulation intent inside metaphor  
- symbolic structures inside story  
- chaotic or emergent structure  
- exploratory tone  
- prototyping language  

These indicators trigger decomposition and routing.

---

## ⭐ **4. Passive Interface Table (v1.0)**

| Component Type | Indicator | Routing Behavior | Notes |
|----------------|-----------|------------------|-------|
| **Mixed‑Altitude Artifact** | semantic + algebra + geometry | Decompose into altitude components | Preserve flavor |
| **Expressive Drift** | chaotic or emergent phrasing | Route semantic components to **Constellation** | Non‑interpretive |
| **Symbolic Leakage** | algebra inside narrative | Route algebraic components to **Triadic‑Core** | Non‑evaluative |
| **Geometric Intuition** | curvature, shape, spatial form | Route geometry to **Simulation‑Suite** | Prevent activation |
| **Simulation Intent** | “run,” “flow,” “execute” | Route simulation intent upward | Non‑activating |
| **Provenance Omission** | missing lineage | Route metadata to **Provenance Layer** | Log omission drift |

This table defines the **Research‑Pilot boundary**.

---

## ⭐ **5. Interface Rules**

### **Rule 1 — Passive Only**  
Coordination does not interpret exploratory meaning.

### **Rule 2 — Non‑Destructive**  
Exploratory artifacts retain their expressive flavor.

### **Rule 3 — Decompose, Don’t Rewrite**  
Mixed‑altitude content is separated, not sanitized.

### **Rule 4 — No Activation**  
Simulation intent is routed but never executed.

### **Rule 5 — Preserve Chaos**  
Research‑Pilot’s exploratory nature is not constrained.

---

## ⭐ **6. Routing Flow**

```
Artifact enters Coordination
   ↓ detect mixed-altitude indicators
Decompose into altitude components
   ↓ route each component upward
Semantic → Constellation
Algebra → Triadic-Core
Geometry → Simulation-Suite
Simulation Intent → Simulation-Suite (non-activated)
Provenance → Provenance Layer
Structure → NDH-Core Architecture
Coordination remains altitude-neutral
```

This is the correct Research‑Pilot routing posture.
